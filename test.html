Post Peek test links

Serve this file over HTTP (the extension does not run on file://) and load it with dots turned on. Every link under a "should" heading is a live check of the host list in src/content.css against POST_RE in src/content.js: the two are meant to agree exactly, so a dot without a popup, or a popup without a dot, is a bug.

Known cosmetic mismatch: dotted, but will not peek

The CSS can only test href substrings, so it cannot check the post id the way POST_RE does. These get a dot and then navigate normally on click. Harmless, but if that ever stops being true, this is where it shows.

  • non-numeric id
  • id longer than 25 digits

Modifier clicks: should always navigate, never peek

Ctrl/Cmd-click, Shift-click, Alt-click and middle-click on this link must open it the normal way.

Links added after load

Nothing watches the DOM: the dot is a CSS rule on href, and the click handler is a single delegated listener on document. So a link inserted now should be dotted the instant it appears, with no observer to miss it. The shadow root case is the one exception: content.css does not cross a shadow boundary, so that link gets no dot, but the click is still matched through composedPath() and should peek.
